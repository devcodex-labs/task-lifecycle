# CAND-20261024-001 v3 提案：覆盖台账须列全部范围，并记录阅读深度的分配依据（在 RULE-20261024-001 v2 基础上增补）
| 字段 | 内容 |
|---|---|
| 状态 | candidate，冻结，未批准；生效须 Rocky 本人对 SHA 批准 |
| 触发来源 | Rocky 在 Capability-graph 会话中提出、由该助手 2026-10-24 13:55 Asia/Shanghai 转达（转达不构成批准）。实例：capability-graph 合规版评审 /workspace/.tmp/capability-graph-review-compliant.md 中，src/ 约 1600 行逐行通读并列 24 个文件台账；test/、examples/、website/ 与大部分 scripts/ 只有一句概括，没有逐文件标出抽查还是未读，也没写为何这样分配阅读深度。据转达，报告已写明“未主张完整审查”；本条未读该报告，以上为转达事实。 |
| 查重 | 不新开 CAND 编号：RULE-20261024-001 v2（已生效）已要求逐文件台账单列读法、抽样标 sampling、截断只报下界；本问题是其缺口，按 RULE-012 作为 001 的增补提案登记。 |
| 缺口 | ① v2 台账只要求列已读文件，未要求列出范围内未读部分，未读部分因此不可见；② 未要求记录逐行、抽查、未读三种深度各自的分配依据。 |
| 拟议增补 | 审查开始前，按本次需求与意图显式决定各目录或文件的阅读深度（逐行 / 抽查 / 未读），把依据写进计划；台账覆盖范围内全部目录与文件（可按目录聚合，但须给出文件数并标深度），未读部分必须列出，不得只写概括句。不得按目录类型套用固定默认深度。 |
| 失败判据 | 台账中出现范围内的目录或文件既未标深度也未列出；或抽查、未读部分没有分配依据；或按目录类型一刀切而无意图说明。 |
| 非适用反例 | 用户已明确指定只读某几个文件，范围外内容不必列入台账。 |
| RULE-006 四项 | 验证：E3，仅核对 RULE-001 v2 正文（active 第 14 行），未读 capability-graph 报告，E4 未验证。合理性：合理，直接针对“未读伪装成已读”的静默遗漏。收益与代价：遗漏可见、可追溯；代价是台账多列未读条目与一段依据，目录聚合可控制篇幅。最优性：优于新开独立候选（会与 001 重复）、优于只在报告末尾写一句“未主张完整审查”（不可逐项追溯）、优于强制全部逐行（违背按意图确定范围，成本过高）。 |
