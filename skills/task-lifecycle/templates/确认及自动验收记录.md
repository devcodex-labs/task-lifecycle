# 独立确认 / Auto 验收记录（追加式示例）

> 这是需要**真实可信决定以后**才可填写的事件字段样例。复制本模板、读取旧会话摘要、补 Hash 或写入“human-confirmed”文字都**不能**自动生成真人授权。每条事件只对明确一个对象和范围生效。

| 字段 | 实际值 |
|---|---|
| Decision ID, Task ID, Project ID | `{真实唯一标识}` |
| Artifact / Plan ID, Version, Actual Path | `{明确对象及有效路径}` |
| Content SHA-256 | `{本轮已实际计算的最终内容SHA；不可计算则hash-unverified/sha-unavailable，并填 实际路径 + 修改时间 + diff 摘要}` |
| Decision Type | `{human-confirmed \| auto-accepted \| rejected \| deferred}` |
| Decision Scope | `{entire-artifact \| 精确被批准章节/字段集合}` |
| Whole Artifact Effective | `{yes \| no；部分确认必须no}` |
| Current Mode / WorkflowDepth & source | `{Confirm/Auto + 选档真实来源}` |
| 放权类配置 | `{校验脚本 status / reasons / 各层 sha256 / 批准核验结果}` |
| Current Trusted User Decision Source | `{来自真实当前会话中明确决定，可定位；不要臆测}` |
| Auto Scope Ref | `{仅合格Auto，任务ID/允许动作/禁止项/有效当前授权来源}` |
| Review/Evidence Ref | `{该对象自审、已批准专项审查、仍缺E4的真实状态}` |
| Observed decision time / unknown | `{可观察时间或unknown}` |
| Supersedes / Current validity | `{旧对象/范围失效依据}` |
| Next Allowed Action | `{不能扩大用户权力的精确下一步}` |

## 多对象确认与防重复审批

- 正式代码交付可按一个关联批次确认：`{Task/Batch ID、Version、上游/WI、精确文件集合与各文件SHA/未验证、真实diff、适用审查测试、范围/整批是否生效、可信决定来源}`。集合/正文变化产生新候选并重核失效范围，部分批准不得整批生效；执行分批不自动产生人批对象，也不授予Git操作权限。审批规则只消费 `../references/确认授权与变更.md`。
- 多份待确认正文，当前用户只说“好的”，对象/版本不唯一时，保持都未获完整批准，请求用户指定准确对象/范围。
- 用户明确指定 A/B/C 的文件及准确SHA，可一次对话分别落独立 Decision 事件。报告事实认可和技术/实施对象全文批准是不同决定。
- 当前计划、源文件、范围和许可均未实质变化，且已有有效同对象批准时记录 `reuse-effective-decision + reason`，不重复询问。
- Auto 绝不能写 `human-confirmed`、批准新产品功能/进化 active/最终用户验收、提升宿主安装/HTTP/Git权限。
- 未经受控写权，不创建本事件文件；真实受管历史留在已核实仓库外位置。
