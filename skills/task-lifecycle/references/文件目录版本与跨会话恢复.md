# 文件目录版本与跨会话恢复

> 此文件是 Task Lifecycle V1 **执行规则**，不是新的需求审批、实际运行记录或额外 API。根依据为用户正式批准的开发需求 V0.18-R2、Usage Contract V0.5-R2 与技术方案 R9-R2。不得以本文覆盖更高优先级的真实用户决定或宿主安全权限。

## 读取条件与职责

**触发**：准备写入任何受管产物、真实源码、测试临时数据，或跨会话/压缩/宿主切换/暂停恢复，以及实际提交/打包/发布候选需检查文件集合时。

**唯一主责**：外置工作区物理路径、Git/worktree/symlink安全、Markdown版本/Hash、dirty保护、重复副作用防护与真实恢复

**直接消费者**：受管路径、工作区偏好、文件版本/确认、验证资源、跨会话恢复。

**联动 Reference**：`确认授权与变更.md` 决定权限与当前审批，`通用规范吸纳与自我进化.md` 决定规则的合法生效。

## 适用时逐项执行

1. 先只读绑定真实 Project ID、Task ID、物理根与同名冲突，检查当前 Git HEAD/dirty、工作树和祖先/嵌套/worktree、symlink/junction；无 Git 且项目存在是合法情形，不虚构仓库。
2. 外置过程目录默认候选为 `<workspace>/.task-lifecycle/<project-id>/<task-id>`，但只有 `realpath`/实际文件系统与 relevant Git 工作树**路径组件**检验通过、宿主允许且用户授权时可创建；前缀相似路径不等于父子目录。不可证时只读阻断/提出安全备选。
3. 正式任务/审查/批准历史放外置；真实源码、测试文件、`.http` 和公开文档仍写**已获许可的合法项目位置**，不能混淆“过程日志外置”与交付文件。
4. 先检查现有文件、同名/大小写/非法字符、权限、工作树 dirty/其他并发变更。原批准正文只读；候选独立版本写后回读、diff/真实SHA在外部事件保存；无法可靠写时标记 pending/blocked，不伪称原子完成。
5. 恢复时从真实路径回读当前批准原件、任务/项目身份、阶段/上游和用户可信决策、实际 diff 与受影响验证、工具实际是否已执行；旧摘要/历史 Markdown/复制审批/旧 Auto 都只是线索。缺证据时停止有副作用动作，保持未验证。
6. 跨会话/相同命令执行结果未知，先检查真实 Git/file/process/HTTP 后果，再决定是否重试；禁止重复扣款/写数据的盲目重放。
7. 仅清理已获权限且证实由本任务启动的临时进程/端口/文件，终止前再检查 PID/启动时间/命令/目标，防止 PID 复用误杀；不使用 `git reset --hard` 或无条件清理 dirty。
8. evolution INDEX/active/history 在安全外置目录，具体生效和回滚由 `通用规范吸纳与自我进化.md` 控制；不能通过写历史文件恢复已撤销权限。
9. **ABS-07 提交/打包/发布候选时**：在明确权限范围内只读检查当前真实文件系统与 Git/worktree 的 `working/staged/untracked/generated/ignored`，区分 `tracked`、`git diff`、index 暂存、实际候选包内容及被 `.gitignore`/打包 `files` 排除的文件；无 Git 项目使用实际源清单和目标包消费检查，Git 专属证据写 `N/A+reason`。按 `验证与证据分流.md` 的 `sourceInventory/requiredDeliverableSet/includedInDeliverable/actualConsumer` 合同核实必需资产、入口和依赖可消费，阻断缺漏或越权后再请求具体修复许可。**不得自动添加 ignored 文件、改 `.gitignore`、覆盖 dirty 或为通过检查而提交/推送**。

**长任务批次安全恢复**：若任务级 Auto 在宿主/上下文容量边界被迫中断，只在已核实真实文件可合法写入时，把本轮已完成的 `BatchID/来源集合Hash/实际目标版本SHA/子条件签署结果与证据/阻断理由/下一批ID/真实可信权限范围` 记入已有外置《任务交接说明》或独立证据索引；不能以日志或进度表替代原批准正文/实际源码。再次启动时重新核实可信用户意图、批准原件、当前文件/dirty及受影响证据，不自动恢复已失效 Auto 或重放结果未知的副作用；无持久工作区或无法自主继续的宿主须明确说明剩余项，不声称后台自动执行。禁止为记录断点擅自创建仓库内状态文件。

## 必须拒绝的反例

- 默认父目录其实在另一 Git 工作树里仍直接创建 `.task-lifecycle`；只凭 `/repo` 是 `/repository` 前缀误判；恢复时相信摘要写着“Auto已授权”；写文件失败却把批准记录写通过；清理未知 PID/工作树未提交修改。



## 偏好与文件命名（REQ-023）

不要求用户编写项目 JSON/YAML。允许以自然语言和可选《工作区约定》《项目约定》表达产物根目录、语言与命名、归档方式、审查偏好、流程深度及任务适用范围；`.http` 策略按对应契约。分别核实真实 Project/Task、作用范围、版本和批准来源，按“当前明确用户指令 → 有效项目约定 → 有效工作区约定 → 缺省推荐”处理。仅本次选择不写长期约定；明确长期保存才生成差异、自审、按模式验收、合法写入并回读实际生效内容。偏好不授权 Auto、Git 或发布，发现项目事实也不等于改用户配置。

正式过程文档的正文与人类可读文件名共同继承当前有效任务/会话语言，按下段同一语言判定及准确作用范围调整，同时保留唯一 Task/Artifact ID 与版本。`package.json`、插件清单、源文件、工具配置及其他技术约定名称不强制翻译或改名；文件名本地化不改变标识、Schema、接口或引用语义。名称碰撞/非法字符仍执行物理路径与版本规则，不覆盖同名历史。

**统一上下文语言**：真实当前用户指令先按其明确范围生效；有效任务选择、项目/工作区语言约定按其来源、优先级及准确范围消费；无有效覆盖时，回复、预检查、确认、正文、表格、交付说明及新过程文件名延续当前任务/会话的真实交流语言，不设置固定中文或英文兜底，也不为回复和产物建立两套默认。上下文不足先沿用仍有效的任务选择，仍不能可靠判断且影响交付时只澄清该歧义。目标文档的有效语言/内容约定及真实读者需要可局部覆盖，技术字面量和原始证据保真；中文交流维护有效英文README时，解释和新过程材料中文、README英文来自同一判定，不为统一表面语言翻译全文。既有明确中文选择仅在其合法作用域保留，不被本规则改成长期偏好。

“本段用英文”等明确局部要求只作用于明示范围，不自动变成任务长期语言或保存为长期偏好。`yes`等短答、英文代码、引用及工具/确认包装本身不构成语言变更指令；保留技术字面量，不自动双语、不翻译历史文件。需要长期保存时仍执行上段独立的明确要求与验收。

**短答须结合真实待决问题解释**：若上文唯一待决事项是“是否把本任务后续答复与过程正文改为英文”这样的语言是/否问题，用户实际回复`yes`应按该问题的肯定选择，在已明示的任务/局部范围生效，不能套用“短答本身不构成指令”一概拒收或重复确认；没有相应语言问题，或多个待决事项使指向不唯一时，仍不得推断语言切换。该语义解释不批准其他正式产物、写入/发布动作或长期偏好保存；文件操作始终核当前宿主权限。

## 升级、并发与正式文件重定位（SC-56/106/112/114）

插件升级/重载或旧任务恢复时，先核实际加载的插件版本/内容指纹、旧任务所用规则/模板版本、批准原件、当前文件与 evolution 的 active/INDEX/history。评估旧记录/规则与新包的兼容、过期证据及所需迁移；兼容有据才在有效原授权范围续接。需要迁移时提出具体旧/新身份、路径、差异、受影响消费者/批准、备份与回退方案，按当前合法范围及模式处理；涉及新产品决定或 active 变更仍独立人批。不能静默重写旧任务/规则、丢历史、把新插件版本当旧批准自动适用于新正文；不兼容或关键事实不明只暂停依赖节点。

同一 Task 跨会话写正式产物时，在现有工作流/交接中标明当前协调写入者、接管依据与可观察会话/任务标识；写前重新比较文件实际内容/版本/指纹与读入基线，核实是否有另一协调者或外部修改。不能确认唯一写入责任或发现冲突时暂停共享写、串行协调/明确接管后再继续；不得让两个会话同时维护确认/交接。此为尽力冲突检查，无分布式锁、跨宿主事务或后台同步保证。

正式 Artifact 被移动、改名或删除后，先依 Task/Artifact ID、批准事件的原路径/版本/字节指纹和实际文件系统重新定位，核查候选是否同一内容、可信来源、合法目标路径及所有消费者引用。仅路径改变且同一内容/原决定仍有效时保留原事件，追加真实位置变更证据并同步引用；不能仅凭同名或最新时间继承批准。原件缺失或内容不同则标 `unverified/blocked`，查可核实备份/历史并按既有授权与版本规则恢复或新建候选；找不到原字节不得用摘要重造“已批准原件”。需新增路径/产品/权限决定时只请求精确缺项，已有效同范围决定不重问。

### 9.1.1 项目/工作区偏好存取与优先级（无 JSON Runtime）

- 路径：在通过真实仓库边界核实的外置 `.task-lifecycle/` 中分别使用工作区《工作区约定.md》和对应真实 Project ID 的《项目约定.md》；不要因为目录名相似而跨项目读取或修改配置。
- 读取：当前可信用户明确指令 ＞ 已确认项目约定（作用范围/版本/确认来源可核实） ＞ 已确认工作区约定 ＞ 推荐缺省（无选档时仍需用户决定）。`workflowDepth` 约定必须区分 **“执行时默认采用”** 与 **“仅推荐、每次由用户决定”**；前者在获批且适用时可作为 `selectedDepth` 的真实来源，后者只能进入 `recommendedDepth`，不能通过字段名/目录位置或模型猜测变成实际执行选择。混合/冲突/来源不明则暂停受影响的受管写入并展示选项。`.http` 策略、语言、归档偏好各自校验取值与适用范围；Auto 不得被长期配置间接启用。
- 保存：用户明确表示仅本次时不写长期约定；明确要求项目/工作区长期保存时，先核实真实身份、外置位置和当前模式/文件权限，生成差异候选，自审→适用确认→写入→**回读**当前文件验证真实生效内容/版本，展示生效范围与来源。失败记 `not-effective`，不使用模型口头承诺。
- 修改/冲突：如果两个会话或外部工具改了同名约定，先比较实际文件与批准原件；版本失效按现有冲突和正式确认规则处理。迁移/重命名后核实真实物理位置和适用 Project ID，不自动复制旧批准。

### 9.2 安全目录选择的确定性验证程序（设计约束）

1. 找到实际选定项目及候选工作区父目录；依赖真实文件系统 `realpath`/等价解析，不只做字符串前缀比较。
2. 在相关路径上按宿主允许执行的命令核对 `git rev-parse --show-toplevel`、`--is-inside-work-tree`，并结合父级仓库、子仓库、worktree 与 symlink/junction 的实际关系形成“禁止落入的 Git 工作树集合”。仅存在 `.git` 文件/目录不能覆盖所有情况。
3. 解析候选 `.task-lifecycle/` 的真实父级和现有组件，对照每个相关 Git 工作树根采用**路径组件**包含判断，不使用 `/foo/bar` 字符前缀错误地匹配 `/foo/barista`。
4. 遇到工作区父目录本身是 Git 仓库、嵌套工作树、跨卷别名、符号链接绕回源码、权限不可验证或非唯一项目时，停止创建并展示可核实的**仓库外**候选及所需人工/宿主授权。
5. 写入前再检查可写性和目标冲突：现有 Task ID 不覆盖，文件同名不同版本走受控新版本；用户已写内容或 dirty 状态保护。
6. 写入后实际 `stat/realpath` 复核真实路径及 Git 状态，记录成功/失败/未知，避免“命令退出 0”但写错位置的错误声明。
7. 后续运行若发现目录被外部移动或成为新 Git 工作树的一部分，暂停后续过程写入并重新核对，不自动迁移全部历史或直接清理。

此机制是**操作时显式调用已有宿主工具的校验步骤**，不是后台守护进程、hook 或永久文件监控。无 Git 项目亦需真实路径、用户选定项目身份与权限校验。

### 9.2.1 名称碰撞与路径跨平台策略

创建安全目录时，以真实绑定的 Project ID / Task ID 为唯一性主键；展示名称先进行 Unicode 规范化、去除或转义实际操作系统禁止的路径字符、剔除 `.`/`..` 及路径分隔符、规避 Windows 保留设备名并限制过长名称；**不能把显示名作为唯一标识**。若候选已存在，实际读取原身份核实是同一任务还是冲突；冲突生成新唯一 ID，绝不覆盖。必要时由真实路径派生辅助短指纹用于首次区分同名项目，但路径迁移后不擅自用新 Hash 创建另一份同一任务——以现有交接来源和真实用户绑定确认进行迁移。Windows/WSL、大小写不敏感磁盘和符号链接别名均按实际文件系统校验，不在设计阶段宣称所有环境已验证。

### 9.3 Markdown 版本和写入原子性边界

- 候选文件修改时先观察现有内容与版本；工具支持时使用临时写入与原子替换以降低半写概率，但**不能宣称跨多个 Markdown 原子事务**。
- 需要覆盖当前候选时必须验证它尚未生效、并且与读入时内容一致；若有人或其他会话更改过文件，停止覆盖并做差异比较。
- 已生效正式产物内容保持可追溯不可静默改写；新正文使用新 `Artifact Version` 或清晰历史路径、更新引用并保留原件；存档不是取消原确认事实。
- 项目源文件/构建产物的写入按现有项目约定和宿主权限处理，必须保护用户未提交的变更，生成文件应找其 canonical 来源。
- 任何部分写入/中断不视作整批完成；按照各文件实际存在性、Hash 和真实 Git 状态分类记录。

### 9.4 交接与恢复的最小回读集

```text
触发：新会话 / 可观察压缩 / 客户端重启 / 被告知换宿主 / 事实完整性不明
  -> 真实工作区与 Project ID / Task ID 绑定
  -> 读取现有《任务交接说明》《工作流方案》以定位原件（它们不是审批本身）
  -> 回读当前动作所依赖的已确认原始需求/Usage Contract/技术方案/实施计划及确认记录
  -> 核对适用内容、版本/Hash、真实批准来源、当前任务模式与权限
  -> 检查项目 Git HEAD/dirty、实际文件、工具结果与待完成外部副作用
  -> 判断哪些审查/测试/批准已过期，需要哪些局部再执行
  -> 有合法条件才恢复受影响写入/正式验收，否则只读与补证
```

长原件需**分段读取所有适用有效约束**并记录已读范围，不因单次消息 Context 不足就凭摘要“补全”未读原件。正常连续会话且原件已确证未变时，只做相关身份/版本检查，避免每一步全量重读。

### 9.5 防重复操作与部分失败

| 实际状态 | 合法续接 |
|---|---|
| `not-started` 有真实证据 | 经当前授权可进入执行 |
| `completed` 且结果/副作用可观察 | 不重复执行；核验结果是否符合当前契约 |
| `failed` 已有原因与可修复前提 | 修复后按已批准的验证/重试条件执行；仅可安全复核的同类暂时性失败重试，**同类最多两次**，记录次数、前提与每次结果，超限停止并报告 |
| `unknown`（退出/网络中断、发布响应未知） | 先查询目标服务/仓库/产物现状，不在未知下重放发布、删除或付款等动作 |
| `partial`（多文件半写入/生成文件覆盖） | 标记实际差异，隔离受影响记录，修复并复核；不改用户已有 dirty |

重试前先核对当前 Task/Work Item、真实文件/Git/目标服务副作用和已发生的同类尝试次数；无法确认是否已执行的 commit、push、付款、发布、删除或破坏性操作不得盲目重试，不能重置计数以伪装新增机会。V1 无精确一次语义；幂等、事务与回滚仍由真实系统或宿主提供，不能靠 Markdown 记录伪造保证。跨会话 Auto 的授权来源必须由真实可信当前用户重新确认或实际证据核对，**不是读取旧 `active` 文本就继续自动改代码**。

### 9.6 本任务临时进程、端口与资源生命周期核验（R8 P1 受控补强）

**触发**：受管任务实际启动测试服务、代理、临时 HTTP 监听、数据库沙箱、进程/子进程，或创建可能持续存在的外部临时资源；普通未启动服务的任务 `N/A + reason`，不强制新建常驻管理器。

**前置**：在当前《执行记录》/《任务交接说明》中记录 `Resource ID / Task ID / actual owner / actual start command / service or port / before-start observable state / permitted scope / planned cleanup / side effects / evidence`，必要时保留精简的一行表格。先核实目标端口/进程是否已有用户所有的实例；若无法确认归属，禁止通过通配符杀进程、清除共享数据或覆盖端口来“准备环境”。仅对本任务实际创建并拥有操作许可的资源执行清理。

**执行与退出**：记录实际启动返回及可观察 PID/监听、受管访问入口、预期生命期；任务完成、取消、暂停后不再使用、测试失败或工具异常时，检查本次实际创建资源是否仍运行，按既定权限和安全方法停止/清理，并验证停止/端口释放/数据未越权变化的实际结果。宿主不支持强制取消、进程归属不明或部分执行结果未知时，停止进一步危险清理，标记 `resource-cleanup-unverified` 或 `blocked`，报告剩余资源、证据和用户可选择的安全清理路径。

**恢复/新回合**：先重新核实现场、Task/资源标识、PID 或等价句柄/占用者身份及实际副作用，不复用可能已经被操作系统分配给其他进程的旧 PID 就盲目杀进程。资源清理不等于源代码回滚或宿主权限扩大；V1 不承诺精确一次、后台 watcher 或跨会话自动守护。

**失败判据**：自己启动的服务遗留且没有真实清理/阻断说明、误杀用户本来运行的进程、清理未知资源时重复执行、将关闭命令退出码等同资源真正释放，均不满足交付质量门禁。使用 PoC-K 的受控环境正反例验证，禁止在用户生产系统为测试人为启动危险服务。
